# Security suite metrics and measured accuracy

Scope: `debug/engines/security`, the 45 adversarial cases (15 hand-written
plus 30 generated by the matrix). The question measured here is whether the
suite **detects** a vulnerability when one exists. A suite that always says
PASS is useless, so passing on the real runtime proves nothing about it.

## 1. Method: deliberate vulnerabilities (mutants)

All cases build their engine, bindings, HTML parser and storage through the
helpers in `lib/src/faults.dart`:

- `newEngine`, `applyDomFault`, `hardenBindings`, `newParser`,
  `newStorage`.
- With no fault active they return the production objects unchanged. A test
  checks that the 45 statuses are identical with and without the helpers'
  zone.
- `withFault(fault, …)` makes them return a runtime with **one known
  vulnerability**.

| Fault | Vulnerability it introduces | Detector cases (contract it breaks) |
|---|---|---|
| `hostGlobal` | `process` is exposed on `globalThis` | `engine.host_globals`, `matrix.global.process` |
| `rawBridge` | `harden()` is skipped: the raw `__nx` bridge stays reachable | `bridge.raw_host_hardened` |
| `innerHtmlExecutes` | `innerHTML` runs `<script>` bodies and `on*` handler attributes | `xss.inner_html_does_not_execute`, `matrix.inner_html.{1–7,9}` |
| `javascriptUrl` | clicking `<a href="javascript:…">` evaluates the URL | `xss.javascript_url_not_executed`, `matrix.url.1` |
| `sharedGlobals` | every new engine is the same runtime | `sandbox.engine_isolation` |
| `microtaskUnbounded` | the per-drain microtask limit is disabled | `limits.microtask_limit` |
| `parserLimitIgnored` | HTML parser input limits are ignored | `limits.parser_input_limit` |
| `quotaIgnored` | `localStorage` quota is not enforced | `storage.quota` |
| `disposeIgnored` | `dispose()` leaves the engine usable | `lifecycle.disposed_engine_rejects_calls` |

The detector lists were fixed from what each fault opens, not from results.
Two corrections were made after the first run, both to the expectation and
not to the suite:

- `internal.callback_globals` checks the `__nx_*` callbacks. These are private
  with or without `harden()`, so it is not a detector of `rawBridge`.
- `matrix.inner_html.8` and `.10` use `javascript:` URLs in `href`/`data`.
  `innerHtmlExecutes` does not open that vector.

**Metrics:**

- **Fault detection:** a fault is detected when at least one of its detector
  cases fails (`FAIL` or `ERROR`).
- **Case sensitivity:** failing detector cases ÷ detector cases.
- **Collateral:** cases outside the list that fail under the fault. They are
  reported, not counted as detections.
- **Specificity:** the baseline run (no fault) must have 0 failures.

## 2. Results

Command (from `debug/engines/security`): `dart run bin/security.dart evaluate`
→ [`debug/datasets/security/audit.json`](../datasets/security/audit.json).
Linux 6.12 x86_64, Dart 3.13.0, QuickJS-ng 0.17.0, 2026-10-26, ~19 s.

| Measure | Result |
|---|---|
| Baseline (no fault) | 44 PASS, 1 SKIP, **0 failing** |
| Faults detected | **9 / 9** |
| Detector cases that failed | **19 / 19** |
| Collateral failures | 0 |

| Fault | Detector cases failing |
|---|---:|
| `hostGlobal` | 2/2 |
| `rawBridge` | 1/1 |
| `innerHtmlExecutes` | 9/9 |
| `javascriptUrl` | 2/2 |
| `sharedGlobals` | 1/1 |
| `microtaskUnbounded` | 1/1 |
| `parserLimitIgnored` | 1/1 |
| `quotaIgnored` | 1/1 |
| `disposeIgnored` | 1/1 |

The result is deterministic: three consecutive CLI runs and the
`dart test` run gave the same rows. The test
`every deliberate vulnerability is caught by its detector cases` fails if any
fault is missed, any detector case passes, or any collateral failure appears.

## 3. Bug found while building the audit

`disposeIgnored` and `sharedGlobals` keep engines alive on purpose. The
first version never released them, so the `evaluate` process finished its
work but did not exit. `withFault` now disposes those engines when the run
ends.

## 4. Limitations

- **Not mutated:**
  - `events.programmatic_*_not_trusted`: the trust flag lives in the Dart
    DOM core. A mutant there would mean editing the test's own object.
  - `limits.infinite_loop_interrupted`: removing the budget would hang the
    run.
  - `bridge.malformed_ids_are_contained`.
  - `platform.flutter_resource_policy`: SKIP outside Flutter.

  These cases have no measured sensitivity.
- **Simulated faults:** the mutants are simulated in JS or by wrapping the
  engine. A real vulnerability could take a shape these cases do not
  exercise. 9/9 means the suite catches **these** nine vulnerability
  classes, not that NativaX is secure.
- **No V8:** only QuickJS-ng was measured. The V8 page engine is not covered
  by this suite.

## Reproduce

```bash
cd debug/engines/security
dart run bin/security.dart evaluate          # writes debug/datasets/security/audit.json
dart test test/security_test.dart            # includes the mutation audit
```
