# Visual comparison metrics and measured accuracy

Scope: `debug/engines/visual_comparison`, specifically the per-pixel
comparison (`lib/src/pixels.dart`) and the difference regions
(`lib/src/regions.dart`). This audit does **not** cover the probe-based
scores (position, layout, colour, design) or the page verdict: those need DOM
probes, and the synthetic dataset has none.

Every number below comes from a command in [Reproduce](#reproduce). The
synthetic results are byte-deterministic. The capture measurements ran on one
machine: Linux 6.12, Google Chrome 152.0.7977.82, NativaX on QuickJS-ng
(`libnx_v8.so` was not built, so V8 did not run), commits `7f6a5fd` and
`3398ab6`.

## 1. Formulas

**Colour difference.** Both images are 8-bit sRGB; alpha is ignored. Each
channel `c/255` is linearized (`c/12.92` when `≤ 0.04045`, else
`((c+0.055)/1.055)^2.4`) and converted to XYZ with the sRGB matrix, then to
CIE L\*a\*b\* with a D65 white `(0.95047, 1, 1.08883)` and the standard `f(t)`
(cube root above `(6/29)^3`, linear below). The per-pixel difference is CIE76:

```
ΔE76 = sqrt((L1−L2)² + (a1−a2)² + (b1−b2)²)
```

Only the common area `min(w1,w2) × min(h1,h2)` is compared.

**Mask.** `mask(x,y) = ΔE76(x,y) > T`, with default `T = 2`. A pixel exactly at
`T` is not masked. `comparePixels()` uses the same `> 2` rule for
`mismatchedPixels`.

**Regions.** Mask pixels are labelled into connected components with the
**8-neighbourhood** (breadth-first flood fill, scanning in row-major order).
Components with fewer than `minArea = 4` pixels are dropped and counted in
`droppedComponents`/`droppedPixels`. Each kept region reports:

- `bbox = [minX, minY, maxX−minX+1, maxY−minY+1]`;
- `pixels`, `meanDeltaE`, `maxDeltaE`;
- up to 8 probe elements whose rect intersects the bbox, ranked by
  `IoU(rect, bbox)`, with the side(s) whose probe has that rect.

Regions are sorted by pixel count, then by `y` and `x`. At most 500 are
listed.

**IoU** of two boxes: `area(A∩B) / (area(A) + area(B) − area(A∩B))`.

**Audit metrics** (`lib/src/audit/evaluate.dart`). For one case, with ground
truth boxes `G` (semantic boxes; see the
[dataset README](../datasets/visual_comparison/README.md)):

- *Truth pixels*: pixels inside some `g ∈ G` whose raw RGB differs between
  the images. Pixels of `g` outside the common area also count, because they
  can never be compared.
- *Pixel level*: `TP = mask ∩ truth`, `FP = mask \ truth`,
  `FN = truth \ mask`, `precision = TP/(TP+FP)`, `recall = TP/(TP+FN)`.
- *Region level*: for each `g`, `bestIoU = max IoU(g, region bbox)` over the
  regions that intersect `g`. `mergedIoU = IoU(g, bbox of the union of those
  regions)`. `g` is *localized* when `bestIoU ≥ 0.5`. A *false region*
  intersects no `g`.
- *Case outcome* (both levels): the expected answer is "different" iff
  `G ≠ ∅`. The pixel level answers "different" iff `mask ≠ ∅`; the region
  level iff at least one region survives the filter. TP/FP/FN/TN follow.

## 2. Dataset

14 synthetic 160×120 pairs, generated by
`debug/engines/visual_comparison/tool/generate_dataset.dart` and committed
under [`debug/datasets/visual_comparison/`](../datasets/visual_comparison/)
with `manifest.json` (ground truth). Each case is a controlled edit of one
base page. The README there describes every case and its truth box. 11 cases
are labelled important, 2 unimportant and 1 identical. The labels are
choices made for this audit, not perception data.

| 40 | 8/1/3/2 | 2934 | 131 | 9008 | 0.957 | 0.246 | 6/1/5/2 | 3/11 | 0.311 | 0.399 | 5 |

Reading:

- Between `T = 0.5` and `T = 2`, recall falls from 0.920 to 0.696. The
  2676 pixels lost are the card fill in `opacity-change` (ΔE 1.18). That is a
  real but imperceptible change.
- `T = 3` turns `unimportant-many` (ΔE 2.77) into a TN. The same value would
  also miss any real change with ΔE in `(2, 3]`. The dataset contains no such
  important change, so it cannot show that cost. That is why the default was
  **not** moved.
- Raising `T` does not monotonically reduce false regions. At `T = 3` and
  `T = 10`, the antialias-noise mask splits into more, smaller components
  (30 and 32 false regions against 17 at `T = 2`).
- `antialias-noise` is a FP at every threshold tested, up to `T = 40`. A
  ΔE threshold cannot separate rasterizer noise from real edits on this data.

Pixel-level results do not depend on `minArea`.

|---:|---|---:|---:|---:|---:|
| 1 (no filter) | 10/2/1/1 | 6/11 | 0.627 | 0.817 | 17 |
| **4** | 8/2/3/1 | 5/11 | 0.534 | 0.664 | 17 |
| 9 | 7/2/4/1 | 5/11 | 0.503 | 0.633 | 16 |
| 16 | 7/2/4/1 | 5/11 | 0.503 | 0.633 | 16 |
| 64 | 6/2/5/1 | 4/11 | 0.412 | 0.542 | 14 |

On real captures (section 6), components smaller than 4 px are almost absent.
Six NativaX-vs-Chromium pages had 1 component below 4 px in total (1 pixel,
on `progress-steps`). Chromium-vs-Chromium and NativaX-vs-NativaX had none.
So on everything measured, `minArea = 4` removes no false regions and hides
the two 1-pixel important cases. The default stays 4, a value chosen before
the audit. The measurements so far argue for `minArea = 1`, but 6 real pages
are too few to change it. The dropped components stay counted in
`regions.json`, and the pixel report still includes those pixels.

## 7. What the engine gets wrong

1. **Single-pixel changes are not regions** (`one-pixel`, `tiny-important`).
   The pixel report counts them (`mismatchedPixels = 1`), but the region
   list does not, so a dropped decimal point appears only as one
   `droppedPixels`.
2. **Rasterizer noise is reported as differences** (`antialias-noise`):
   3258 FP pixels and 15 false regions at every `T ≤ 40`. On real
   NativaX-vs-Chromium pages, text antialiasing produces the same kind of
   regions. They cannot be told apart from real edits without another signal
   (for example, the probe geometry).
3. **Large imperceptible tints dominate** (`unimportant-many`): 63.45 % of
   pixels are mismatched for a ΔE 2.77 background tint. `mismatchedPct` is a
   measure of how much changed, not of how much it matters.
4. **Moves and scaling fragment** (`layout-shift`, `scaling`). No single
   region is localized (best IoU 0.329 and 0.198). Only the union of the
   intersecting regions matches (0.958 to 1.000). Consumers should look at
   regions grouped per element, not region by region.
5. **Glyph changes are partly dropped** (`text-change`). The 2 → 7 diff
   splits into 5 components and 4 of them are below `minArea`. The kept one
   covers 0.343 of the glyph cell.
6. **Imperceptible parts of a real change are missed** (`opacity-change`):
   the card is localized (IoU 1.0 from its border), but the fill (ΔE 1.18) is
   below `T`. Pixel recall is 0.142.
7. **Size differences are invisible to pixels** (`viewport-size`). Only the
   common area is compared. The full pipeline relies on the hard
   `screenshot-size` environment check, which makes the page `INVALID`.
8. **Fixed during this audit:** `comparePixels()`, `pixelCsv()` and the
   background estimate indexed both images with the common width. Pairs of
   different widths therefore compared shifted rows: `viewport-size`
   reported 33.87 % mismatched pixels for identical content. Fixed in
   `242a157` with a regression test. Same-size pairs, the normal case, were
   never affected.

## 8. Limitations of this audit

- The dataset is synthetic: flat colours, a bitmap font, no real
  antialiasing, gradients, images or shadows. Its numbers describe the
  detector on these 14 cases only, and they are not an accuracy figure for
  real pages.
- The truth boxes and the important/unimportant labels are the audit's own
  definitions. Real perceptual ground truth would need human ratings.
- Probe-based scores, verdicts and element attribution in `regions.json`
  are not evaluated here. Attribution is covered by unit tests only.
- The real-page measurements cover one machine, one Chrome build, QuickJS
  only, light scheme, and 10 + 5 pages.

## Reproduce

```bash
cd debug/engines/visual_comparison
dart run tool/generate_dataset.dart    # deterministic; dataset_test checks drift
dart run tool/audit_dataset.dart       # writes debug/datasets/visual_comparison/audit.json

# From the repository root, with Google Chrome installed:
dart run debug/engines/visual_comparison/bin/visual_check.dart \
  --self-check --suite 50projects50days --limit 10 --out /tmp/vc-self
dart run debug/engines/visual_comparison/bin/visual_check.dart \
  --suite 50projects50days --limit 5 --out /tmp/vc-a
dart run debug/engines/visual_comparison/bin/visual_check.dart \
  --suite 50projects50days --limit 5 --out /tmp/vc-b
```

For the cross-run comparison, compare `chrome.png`/`nativax.png` of
`/tmp/vc-a` and `/tmp/vc-b` with `deltaMap()` + `findRegions(minArea: 1)`,
or with `cmp`.
