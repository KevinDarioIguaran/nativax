# Visual comparison accuracy dataset

Synthetic, deterministic image pairs with known difference regions, used to
audit `debug/engines/visual_comparison` (the per-pixel ΔE in `pixels.dart` and
the region detector in `regions.dart`). Results and formulas are in
[`debug/architecture/metrics-visual.md`](../../architecture/metrics-visual.md).

Nothing here is a browser capture. Every image is drawn by
`lib/src/audit/dataset.dart` from a 160×120 "page": a dark header with
`PRICE` (scale 2), a blue `OK` button, the text lines `TOTAL 42` and
`PRICE 1.50` (5×7 bitmap font, 6 px advance), a light card with a border,
`SAVE` and a green bar, and a 1 px footer rule. No antialiasing except in the
`antialias-noise` case. Randomness comes only from a fixed LCG seed.

```bash
cd debug/engines/visual_comparison
dart run tool/generate_dataset.dart   # rewrites the PNGs and manifest.json
dart run tool/audit_dataset.dart      # rewrites audit.json from the PNGs
dart test test/dataset_test.dart      # fails if the files drift
```

## Layout

```
<case>/reference.png   expected render
<case>/actual.png      render under test
manifest.json          cases, descriptions, ground-truth boxes
audit.json             detector results (generated by audit_dataset.dart)
```

Boxes are `[x, y, w, h]` in pixels.

## Ground truth

`truth` lists the **semantic** boxes a reviewer would point at as
"different": the element or glyph cell, not the tight bbox of changed pixels.
An empty list means "nothing actionable". This applies both to the identical
pair and to differences that are real in RGB but do not matter.

| Case | Kind | Change | Truth box(es) |
|---|---|---|---|
| `identical` | identical | none, byte-identical | — |
| `one-pixel` | important | one white pixel at (120,100) becomes black | `[120,100,1,1]` |
| `small-block` | important | 6×6 red block inside the card | `[132,64,6,6]` |
| `layout-shift` | important | the 60×52 card moves 24 px down (old/new overlap 28 px) | union of old and new card: `[90,28,60,76]` |
| `missing-component` | important | the 40×16 OK button is not drawn | `[10,30,40,16]` |
| `extra-component` | important | a 22×11 red `NEW` badge is added | `[60,30,22,11]` |
| `text-change` | important | `TOTAL 42` → `TOTAL 47` | glyph cell `[52,56,5,7]` |
| `color-change` | important | button `rgb(37,99,235)` → `rgb(37,82,200)` (ΔE76 11.19) | `[10,30,40,16]` |
| `opacity-change` | important | card composited at opacity 0.6 (fill ΔE 1.18, border ΔE 14.86) | `[90,28,60,52]` |
| `scaling` | important | whole page scaled ×1.05 from the top-left corner (nearest neighbour) | whole canvas `[0,0,160,120]` |
| `viewport-size` | important | actual capture is 152×120: same content, 8 px narrower | missing strip `[152,0,8,120]` |
| `antialias-noise` | unimportant | each edge pixel is mixed 15–45 % with a neighbour, imitating another rasterizer | — |
| `tiny-important` | important | `PRICE 1.50` → `PRICE 1 50`: the 1 px decimal point disappears | glyph cell `[52,70,5,7]` |
| `unimportant-many` | unimportant | white background → `rgb(247,247,247)` (ΔE76 2.77) on ~63 % of pixels | — |

"Important" and "unimportant" are labels chosen for this audit. They are
not facts about human perception. `antialias-noise` and `unimportant-many`
exist to show what a plain pixel threshold cannot tell apart.
`viewport-size` exists because the pixel comparison only covers the common
area; in the full pipeline the hard `screenshot-size` check catches it.
