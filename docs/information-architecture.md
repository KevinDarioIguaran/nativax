# Information architecture

Status: canonical for repository formats and AI context delivery.
Scope: how NativaX stores, derives, retrieves, and measures information. Product
behavior is out of scope.

Evidence: `progress/reports/information-architecture-latest.json` (generated by
`debug/logic/ia_audit.py`), plus the commands and results in
[Validation](#validation).

## 1. Method

The audit inspected the repository at `HEAD` `f47240e` on 2026-10-25:

- tracked files, sizes, extensions, and top-level owners;
- producers and consumers of diagnostics, benchmarks, conformance, reports,
  agent instructions, and docs;
- generated artifact volume under `debug/artifacts/`;
- representative reads for an agent (always-on instructions, status, latest
  conformance, benchmark history);
- byte size, line count, and token cost (exact if `tiktoken` is installed,
  otherwise a labelled `ceil(UTF-8 bytes / 4)` estimate).

No historical evidence was deleted. The previous chronological
`progress/status.md` is preserved byte-for-byte at
`progress/history/status-2026-10-25.md`.

## 3. Measured baseline

Tracked tree: **1,000 present files, 33.7 MB** (one tracked file is absent from
disk: `repomix-output.xml`, a pre-existing working-tree deletion). The largest
tracked groups are example game assets, QuickJS C sources, Dart sources, and
Markdown (`114` files, `0.93 MB`).

Generated artifacts on this machine: **~1.1 GB**, dominated by visual runs
(`541 MB`) and audit runs (`256 MB`). Conformance artifacts are `140 MB`
(`34 MB` results; the rest is downloaded suites); the derived context index is
about `69 KB`.

The extractors currently index **26/26 run manifests**, **93/93 conformance
summaries** (92 legacy, 1 compact), and **78 maintained Markdown files**.
Extraction is structural: it reads validated fields and headings, not free-form
prose, and tests cover the legacy/new summary paths, `runKey` separation,
relative provenance paths, and budget truncation. It is not a semantic
question-answering index; no recall claim is made for arbitrary questions.

The largest single information defect was conformance duplication:

| Run | Legacy `summary.json` | Canonical JSONL | New metadata summary | Summary saving |
|---|---:|---:|---:|---:|
| WPT URL, 896 tests | 197,504 B / 49,376 est. tokens | 135,424 B | 289 B / 73 est. tokens | 99.9 % |
| Test262, 21,098 tests | 5,576,040 B | 3,995,624 B | 466 B (preview) | ~100 % |
| html5lib, 6,827 tests | 1,730,022 B | 1,262,528 B | 390 B (preview) | ~100 % |

The URL pair (summary + JSONL) fell from 332,928 B to 135,713 B: **59.2 %**
less. The per-test rows were already canonical in JSONL; the old summary
repeated them, including long failure details. Historical summaries stay
untouched: they are evidence, and readers still accept them.

Always-read context was also oversized:

|---|---:|---:|---:|
| `progress/status.md` | 37,920 B / 9,480 est. tokens | 5,531 B / 1,383 est. tokens | −85.4 % |
| `.agents/README.md` | 4,308 B / 1,077 est. tokens | 3,321 B / 831 est. tokens | −22.9 % |

`progress/status.md` had become a chronological log duplicating
`progress/log.md`; the full snapshot moved to `progress/history/` and the live
file now carries the current table, blockers, and links.

## 4. Format policy

The policy chooses the smallest representation that keeps the required
consumers correct. It is not a mandate to convert source code or public docs.

| Information | Canonical format | Transport / derived | Why |
|---|---|---|---|
| Source, tests, fixtures | Native source | — | Compilers, tooling, debugging; compact encodings would break semantics |
| Public and technical docs | Markdown | HTML preview (`render_report.py`) | Reviewable, linkable, diffable; HTML is derived |
| Live status / history | Markdown | Context index | Humans need prose; agents need the short current file |
| Run metadata | JSON + JSON Schema | JSONL index | Explicit fields, validation, cheap projection |
| Per-test conformance rows | JSONL, one object per test | Markdown report with bounded failure details | Append-friendly, streaming, one row per line; report is derived |
| Benchmark samples | JSON/JSONL; CSV for spreadsheets | Markdown/SVG | Existing engines and GUI already read these |
| Benchmark/security/leak history | Per-run directory + manifest JSON | `runs.jsonl` index | Reproducibility and immutable evidence |
| Large numeric arrays / screenshots | Existing binary formats (PNG, JSON) | HTML/Markdown report | Avoid base64 and text expansion |
| Agent instructions | Markdown | On-demand skills | Harness compatibility and explicit rules |
| Machine-generated summaries | JSONL/JSON with schema ids | `brief` projection | Provenance to canonical files, bounded size |
| Validation contracts | JSON Schema | Python subset validator | No new dependency; schemas already shipped |

Not introduced:

- **SQLite**: current history is 26 run manifests and 93 conformance summaries.
  A JSONL index answers the queries in one pass; an embedded database would add
  a binary artifact, migration, and inspection cost without a measured need.
- **Parquet/columnar formats**: no repeated analytical scan over millions of
  rows; the largest dataset (Test262) is already JSONL and is read whole only
  for a run comparison.
- **MessagePack/CBOR/Protobuf**: no binary transport boundary; JSON is the
  existing tool boundary and the byte savings would not repay schema/tooling.
- **Custom compact syntaxes**: no evidence they improve comprehension; explicit
  field names are retained.

| `nativax/conformance-run-summary@1.0` | `debug/engines/compatibility/schemas/run-summary.schema.json` | New |
| `nativax/run-index@1.0` | `debug/logic/schemas/run-index.schema.json` | New |
| `nativax/conformance-index@1.0` | `debug/logic/schemas/conformance-index.schema.json` | New |
| `nativax.doc.v1` | `debug/artifacts/index/docs.jsonl` record (documented above) | New |
| `nativax.inventory.v1` | `context inventory` output | New |
| `nativax.context.brief.v1` | `context brief` output | New |

The JSONL records use their own `schema` value (`nativax.run.v1`,
`nativax.conformance.run.v1`, `nativax.doc.v1`); the JSON Schema files use the
`nativax/run-index@1.0` and `nativax/conformance-index@1.0` ids.

Conformance summary rules:

- Writers emit metadata only: `suite`, `startedAt`, `durationMs`, `counts`,
  `total`, `passRate`, optional suite commit/version/command, and `resultsFile`.
- `resultsFile` is the basename of the sibling JSONL; per-test rows are never
  duplicated.
- Readers accept historical summaries with an embedded `results` array and
  summaries with no `resultsFile` (sibling name fallback). If a summary
  declares `resultsFile` but the file is missing, the loader returns no
  baseline instead of fabricating an empty result set.
- `counts` uses `PASS`, `FAIL`, `SKIP`, `ERROR`; `passRate` is PASS divided by
  PASS+FAIL (SKIP excluded); the schema enforces `0..100`.
- Missing and null remain distinct: absent optional metadata is omitted, not
  written as `null`.
- Historical files are not rewritten or validated against the new schema; they
  are read by the compatibility loader.

Run index rules:

- One JSON object per line; each record carries `schema`, `runId`, `area`,
  `kind` (`benchmark` or `archive`), `status`, `engine`, `revision`,
  `archivedAt`, `files`, `bytes`, `source`, and `path`.
- Records sort newest first by `runId`; the index is regenerated, never hand
  edited.
- `path` is relative to the repository root. Timestamps keep their original
  offset or `Z`.

Conformance index rules:

- One record per summary; `runKey` is `suite` plus the command when present.
  WPT uses one suite name for different directories, so grouping by `suite`
  alone hides runs.
- Smoke runs under 100 tests are excluded by default; `--all` includes them.
- `path` points at the canonical summary; `resultsFile` points at the rows.

## 6. AI context delivery

Progressive disclosure is implemented in `debug/logic/context.py`:

1. **Index** (`brief`): repository counts, top-level sizes, newest runs,
   current conformance metadata, and document titles. Bounded by `--budget`
   estimated tokens; truncation is explicit.
2. **Summary** (`runs`, `conformance`, `docs`): filtered, paginated records with
   relative paths.
3. **Interface** (`docs/README.md`, schemas, engine READMEs): exact contracts.
4. **Implementation**: source at the cited path.
5. **Evidence**: JSONL rows, run directories, reports, screenshots.

Commands:

```bash
python3 debug/run.py context brief --budget 2000
python3 debug/run.py context runs --limit 10
python3 debug/run.py context conformance --limit 10
python3 debug/run.py context docs --limit 20
python3 debug/run.py context measure progress/status.md docs/README.md
python3 debug/run.py context index
```

The 2,000-token brief on this tree is **1,915 estimated tokens / 7,680 B**
(7 conformance suites, 7 runs, 8 document records after truncation). It does
not contain failure details; it names the canonical summary and JSONL. That is
intentional: a model retrieves the detail only when the task needs it.

## 7. `.agents/` assessment

- Always-on cost is `AGENTS.md` + `CLAUDE.md` = **5,863 B**, about **1,466
  estimated tokens**. This is the right layer for non-negotiable constraints,
  workflow, commands, and skill selection.
- `.agents/` Markdown totals 64.8 KB (skills plus references), but loads on
  demand; it does not consume every session.
- Duplication removed: `.agents/README.md` no longer mirrors the directory
  tree (a filesystem listing that drifts). The skills table remains the map.
- Remaining duplication is deliberate: the short skill table appears in
  `AGENTS.md` and `.agents/README.md`, and the quick rules appear in both. The
  duplication is small and prevents a mandatory rule from being buried behind
  an extra read. If it grows, make `AGENTS.md` authoritative and reduce the
  README to a pointer.

## 8. `debug/` data and report flow

```text
engine run
  -> debug/benchmarks/<area>/<run_id>/ (result files + manifest)
  -> debug/artifacts/runs/<area>/<run_id>/ (immutable evidence + reports)
  -> debug/artifacts/index/runs.jsonl (derived)
  -> context brief / runs (AI)
  -> progress/reports (human, derived)

conformance run
  -> debug/artifacts/conformance/results/<suite>-<stamp>.jsonl (rows)
  -> .../<suite>-<stamp>.summary.json (metadata)
  -> .../<suite>-<stamp>.md (human report)
  -> debug/artifacts/index/conformance.jsonl (derived)
  -> progress/reports/<suite>-latest.md (derived convenience copy)
```

The `latest` Markdown copies are convenience, not canonical. The index orders
by `startedAt` from summaries. This avoids treating a stale copied report as
the newest run; it also exposed stale `progress/reports/wpt-*-latest.md` copies
in the working tree, which remain a documented limitation until regenerated.

## 10. Migration and compatibility

- **Conformance writers** changed; historical files unchanged. `RunSummary.load`
  merges `resultsFile` when inline results are absent and still accepts legacy
  summaries. `--baseline` works with both. `quality_gate.py` reads `counts` and
  `passRate`, which the new summary preserves.
- **New indexes** live under gitignored `debug/artifacts/index/`; deleting them
  is safe and `context index` rebuilds them. Queries fall back to canonical
  evidence when the index is stale.
- **No public command removed.** `python3 debug/run.py context ...` is additive.
- **No historical evidence deleted.** The old status is byte-identical in
  `progress/history/`; legacy summaries and run directories remain.
- **No new runtime dependency.** The tools use the Python standard library; the
  optional `tiktoken` import only improves measurement labels.

## 12. Remaining inefficiencies and limitations

1. **Historical conformance summaries remain large** (92 legacy files, 18.1 MB
   of summaries). They are preserved as evidence; only new runs use the compact
   form. A lossless migration could strip `results` after verifying
   the JSONL copy, but that is a separate, reviewable data migration.
2. **`progress/reports/*-latest.md` can lag** the newest archived run. They are
   generated convenience copies; the index and `quality_gate` use summaries.
   Regenerating them requires a full suite run.
3. **Token counts are estimates** on this machine: no `tiktoken`,
   `tokenizers`, or `transformers` is installed. The report labels
   `estimate:utf8_bytes/4`; install a tokenizer to obtain exact counts without
   changing the tool.
4. **`progress/log.md` is 52 KB** and grows every session. The context/docs
   index makes it retrievable by heading, but periodic rotation into
   `progress/history/` is still warranted.
5. **Generated artifacts are 1.1 GB** and gitignored. Pruning is explicit
   (`storage.prune`), never automatic; screenshots dominate.
6. **WPT run identity** depends on the command string. `runKey` separates
   `dom/nodes`, `css/selectors`, and `dom/events`; a future runner should write
   an explicit `scope` field rather than relying on the command.
7. **No exact historical before/after** for every category: only the files with
   a measurable baseline (status, agent README, URL summary, largest legacy
   preview) are quantified. The rest is recorded as inventory, not as a claimed
   saving.
8. **`docs/status.md` remains a historical 10 KB file.** It is labelled as
   historical and is not part of the live context; moving it would break
   existing links for little gain.

## 13. Maintenance

- New structured output: define a schema id/version, a writer, a reader, and a
  test; add it to the tables above.
- New run area: write a `manifest.json` through `debug/logic/storage.py` or the
  engine helper; do not add a loose result file at the root.
- New derived report: write it under `debug/artifacts/` or `progress/reports/`
  as a generated convenience copy, and link to canonical evidence.
- After changing docs or adding a run: `python3 debug/run.py context index`.
- Do not claim token or size savings without `ia_audit.py` output or an
  equivalent measurement.
